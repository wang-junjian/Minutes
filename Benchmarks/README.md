# 推理性能对照

## 方法

- 机器：Apple M2 Max，arm64；应用和两个引擎均在本机运行。
- ASR：使用同一组 16 kHz、单声道、float32 PCM，包含 11.369 秒和 25 秒中文样本。每个样本预热 1 次，再测 5 次，报告中位数（范围）。
- LLM：使用固定中文会议转写和固定四节 Markdown 纪要 Prompt，`temperature=0.3`、`max_tokens=4096`。预热 1 次，再测 5 次。TTFT 从首个 ready 事件到首个非空内容块；token 数由对应 tokenizer 计算。
- 内存：完成重复请求后采样 `ps RSS` 和 macOS `phys_footprint`； footprint peak 取系统报告值。RSS 采样不是连续峰值监控，比较时应保持相同方法。
- 当前样本没有人工校对参考文本，因此本表不虚构 CER/WER；输出文本另做一致性检查。

## 旧版基线（PyTorch/MPS + MLX）

ASR：Qwen3-ASR-1.7B，FP16；模型加载 4.0 秒。

| 音频时长 | 请求耗时中位数（范围） | RTF 中位数 |
|-|-|-|
| 11.369 秒 | 1.061 秒（1.058–1.080） | 0.093 |
| 25 秒 | 1.909 秒（1.895–1.917） | 0.076 |

两个样本重复识别的输出完全一致。25 秒样本输出包含园区实时指标、虚拟电厂定义和负荷聚合内容；与旧版功能基线一致。

LLM：Qwen3.5-4B-OptiQ-4bit；模型加载 1.3 秒。

| TTFT 中位数（范围） | 总耗时中位数（范围） | 生成速度中位数（范围） |
|-|-|-|
| 0.366 秒（0.365–0.370） | 2.996 秒（2.825–3.347） | 85.30 token/s（85.19–85.38） |

输出包含摘要、决议、行动项和关键词，未出现思考内容。

| 引擎 | 采样 RSS | phys_footprint | 系统报告 footprint peak |
|-|-|-|-|
| 旧 ASR | 1,074,512 KB（约 1.02 GiB） | 6,245 MB | 6,780 MB |
| 旧 LLM | 3,537,968 KB（约 3.37 GiB） | 3,543 MB | 4,182 MB |

## 原生版本（audio.cpp + llama.cpp）

### LLM：Qwen3.5-4B Q4_K_M + Metal

使用与旧版相同的 Prompt 和输出上限。llama.cpp 首次请求的 TTFT 为 0.568 秒；后续重复请求命中 Prompt cache，下表报告预热后的 5 次结果。首 token 与总耗时使用服务器 `prompt_ms` / `predicted_ms`，生成速度使用服务器 token 计数，不与字符数混用。

| TTFT 中位数（范围） | 总耗时中位数（范围） | 生成速度中位数（范围） |
|-|-|-|
| 0.024 秒（0.024–0.043，含缓存命中） | 2.755 秒（2.442–3.108） | 80.76 token/s（80.66–80.80） |

输出包含全部四个 Markdown 小节，无思考内容。与旧版相比，本组请求的总耗时中位数下降约 8%，但纯生成速度从 85.30 降为 80.76 token/s（约慢 5%），因此不能只依据“原生”宣称所有指标都更快。

| 引擎 | 采样 RSS | phys_footprint | 系统报告 footprint peak |
|-|-|-|-|
| 新 LLM | 4,060,080 KB（约 3.87 GiB） | 1,284 MB | 1,284 MB |
| 旧 LLM | 3,537,968 KB（约 3.37 GiB） | 3,543 MB | 4,182 MB |

新 LLM 的 RSS 高于旧版，但 `phys_footprint` 明显更低；两种口径均保留，避免把 mmap/统一内存差异误写成单一的内存结论。

### ASR：Qwen3-ASR-1.7B Q8_0 + Metal

| 音频时长 | 请求耗时中位数（范围） | RTF 中位数 |
|-|-|-|
| 11.369 秒 | 0.545 秒（0.544–0.554） | 0.048 |
| 25 秒 | 0.957 秒（0.954–1.001） | 0.038 |

相同输入下，两个场景耗时中位数均约为旧版的一半；25 秒音频从 1.909 秒降为 0.957 秒。

重复输出一致。11 秒样本中，新版“通义千问”修正了旧版“通亿千问”。25 秒样本存在量化差异：旧版开头为“数据合在一起…总出力…”，新版为“时聚合在一起…总处理…”，新版另有“核电状态”的识别结果。主体内容一致，但个别词错误说明 Q8 不能视为与 FP16 完全等价，后续仍应使用带人工校对文本的会议集评估 CER。

| 引擎 | 采样 RSS | phys_footprint | 系统报告 footprint peak |
|-|-|-|-|
| 新 ASR | 3,241,216 KB（约 3.09 GiB） | 3,065 MB | 3,065 MB |
| 旧 ASR | 1,074,512 KB（约 1.02 GiB） | 6,245 MB | 6,780 MB |

新 ASR 的 footprint 约下降 51%，但 RSS 上升；与 LLM 一样，两种口径都保留。

## 原生闭环回归

以下命令直接使用应用的真实 `EngineWorker` 与 `EngineClient` 源码，依次完成原生进程启动、健康身份检查、25 秒中文 ASR、LLM SSE 和进程停止：

```bash
MINUTES_SMOKE_ASR=/path/to/real_zh_16k.f32 \
MINUTES_SMOKE_LLM=1 \
bash scripts/verify_native.sh
```

`MINUTES_SMOKE_ASR` 可选；省略时只验证两个 worker 的启动与停止。`MINUTES_SMOKE_LLM=1` 会检查两个 Markdown 小节并拒绝思考标签。再设置 `MINUTES_SMOKE_MAP_REDUCE=1` 可触发超过 12000 字符的多段压缩与汇总。该工具不使用 XCTest 宿主，因此不会出现环境变量未传入而导致测试误跳过的情况。
