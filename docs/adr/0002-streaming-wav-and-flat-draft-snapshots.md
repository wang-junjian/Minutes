# 会议音频采用流式 WAV 与平铺草稿快照

会议音频从录制开始持续追加写入单个 PCM16 / 16 kHz / 单声道 WAV 文件，正常结束时回填头部长度，崩溃后启动时按文件实际大小确定性修复头部；草稿快照以 `<UUID>.draft` 平铺在 Meetings 目录，与已完成会议 `<UUID>.json`、音频 `<UUID>.wav` 并列，启动时发现草稿即判定为中断会议，无需心跳或锁文件。

选择 WAV 而非 AAC：无编码依赖、`AVAudioPlayer` 直接可播、可重喂 ASR，且崩溃后的头部修复是确定性操作；AAC 的编码写入与容器崩溃修复更脆弱。选择平铺而非每场会议一个目录：既有会议 JSON 零迁移，且 `.draft` 扩展名天然避开 `MeetingsStore.load` 的 `.json` 后缀筛选，草稿不会误入历史列表。

## Consequences

- 音频体积约 1.9 MB/分钟（≈115 MB/小时），压缩（如 AAC）留作后续增强。
- 恢复续录时从 WAV 读入未识别尾部重建缓冲，不重新识别已落定部分；音频偏移与片段时间戳继续遵循 ADR-0001 的录制时间轴。
- 会议完成或放弃必须删除草稿；删除历史会议必须级联删除音频，否则放弃/删除语义被破坏。
