# 会议音频保存、回放与崩溃恢复

Status: ready-for-agent

## Problem Statement

用户召开会议时，音频与转写文本只存在于内存中，正常业务仅在结束事务末尾保存一次完整会议 JSON。应用崩溃或被强制退出后，整场会议的音频与文本全部丢失，无法挽回。同时，会议完成后用户无法回听原音，无法核对转写与纪要是否准确，也无法将录音作为会议档案留存。

## Solution

会议录制期间，音频从第一个采样起持续写入磁盘，正式片段落定与定时兜底将转写进度保存为草稿快照。崩溃后下次启动时，应用明确列出中断会议，由用户选择继续录制、结束并生成纪要或放弃；续录不重复识别已落定部分。会议完成后，历史详情页提供内嵌播放器回听原音；音频随会议删除，也可单独删除以释放空间，并可在 Finder 中显示以便自行导出。音频与文本一样不离开本机。

## User Stories

1. 作为用户，我希望录制一开始音频就自动持续保存到磁盘，以便应用崩溃时整场录音不会丢失。
2. 作为用户，我希望暂停期间不写入音频、恢复后音频保持连续，以便音频偏移与正式片段时间戳始终一致。
3. 作为用户，我希望会议完成后音频仍然保留，以便日后随时回听校对。
4. 作为用户，我希望历史详情页有内嵌播放器（播放/暂停、进度拖动、倍速、总时长），以便快速定位并回听感兴趣的段落。
5. 作为用户，我希望音频播放时的进度与录制时间轴一致，以便对照转写原文核对内容。
6. 作为没有音频的旧会议的所有者，我希望详情页优雅降级（不显示播放器或明确显示无音频），以便既有会议不受影响。
7. 作为用户，我希望能单独删除音频而保留转写与纪要，并有不可恢复的二次确认，以便释放磁盘空间。
8. 作为用户，我希望删除会议时音频一并删除，以便不留下无人管理的残留文件。
9. 作为用户，我希望能在 Finder 中显示音频文件，以便自行复制导出。
10. 作为用户，我希望音频单独删除后详情页明确显示音频不可用，以便不会误以为仍可回放。
11. 作为用户，我希望每个正式片段落定时立即保存草稿，以便崩溃时最多丢失未落定的临时内容。
12. 作为用户，我希望长时间无段落落定时也有定时兜底保存（约 15 秒），以便持续讲话的场景同样受保护。
13. 作为用户，我希望自动保存失败时看到明确警告但录制不被阻断，以便我知晓风险并继续会议。
14. 作为用户，我希望崩溃后重启看到恢复面板，列出每个中断会议的开始时间与已保存时长，以便决定如何处理。
15. 作为用户，我希望选择"继续录制"后先看到已恢复的正式片段与时长、处于暂停态，以便确认内容无误后手动继续开麦。
16. 作为用户，我希望续录时未识别的尾部音频重新识别、已落定部分不重复识别，以便转写完整且不产生重复片段。
17. 作为用户，我希望续录的音频追加到同一文件、会议开始时间与累计时长延续，以便会议仍是一份连续档案。
18. 作为用户，我希望对中断会议选择"结束并生成"时走正常结束事务，以便获得与正常完成一致的纪要与保存行为。
19. 作为用户，我希望没有正式片段的中断会议也能恢复（继续录制或放弃），以便"录了多久但没说话"的场景不丢音频。
20. 作为用户，我希望对无正式片段的中断会议选择"结束并生成"时遵循空会议规则（不生成、不保存、不完成），以便不产生空白纪要。
21. 作为用户，我希望放弃中断会议时其草稿与音频被彻底删除，以便放弃语义不被残留文件破坏。
22. 作为用户，我希望能"稍后处理"关闭恢复面板，以便先处理别的事；草稿保留且下次启动再提示。
23. 作为用户，我希望中断会议不出现在历史列表，以便历史列表只包含正式完成的会议。
24. 作为用户，我希望正常完成、正常放弃或正常退出后重启不再出现恢复提示，以便提示只在真正中断时出现。
25. 作为用户，我希望多场中断会议能在恢复面板中逐个处理，以便连续崩溃的场景也能恢复。
26. 作为用户，我希望崩溃导致音频文件头损坏时应用在启动时自动修复，以便恢复后音频可完整播放。
27. 作为用户，我希望音频与文本一样不离开本机，以便会议隐私得到保护。

## Implementation Decisions

### 文件布局与格式（遵循 ADR-0002）

- 保持现有 Meetings 目录平铺结构，零迁移：已完成会议 `<UUID>.json`、会议音频 `<UUID>.wav`、草稿快照 `<UUID>.draft`。
- 音频为 PCM16 / 16 kHz / 单声道 WAV，从录制开始持续追加写入；正常结束与暂停时回填头部数据长度；启动时按文件实际大小确定性修复头部。体积约 115 MB/小时，第一版不压缩。
- 草稿扩展名 `.draft` 避开 MeetingsStore 加载的 `.json` 后缀筛选，草稿不会误入历史列表。
- 草稿内容 = 完整 Meeting（正式片段、累计录制时长、createdAt、标题）+ 已落定音频偏移；不保存 interim 与在飞识别状态。
- 崩溃检测：正常完成、放弃、正常退出二选一均清理草稿，故启动时发现任何草稿即判定为中断会议，无需心跳或锁文件。

### 模块与接口

- **新增会议文件存取层**：唯一新增模块，负责流式 WAV 写入与头部回填/修复、草稿读写与删除、中断会议扫描、单独删除音频、删除会议时的级联清理、Finder 定位路径。使用真实文件系统，不引入文件系统抽象协议。
- **MeetingSession**：在现有采集消费循环（送识别缓冲之前已拿到完整 chunk 的位置）挂接音频写入；正式片段落定时写草稿，另加可配置间隔的定时兜底（默认 15 秒）；结束事务完成与放弃时清理草稿；支持从中断恢复的构造路径——按草稿恢复正式片段与时长，从 WAV 读入已落定偏移之后的尾部重建当前缓冲，续录追加同一 WAV。
- **MeetingsStore**：加载行为不变；删除会议级联删除音频与草稿；新增单独删除音频操作（保留 JSON）。
- **应用启动与恢复协调**：启动时经存取层扫描草稿并修复 WAV 头部；存在中断会议时显示恢复面板，提供继续录制（恢复为暂停态，手动继续才采集）、结束并生成（走现有结束事务）、放弃（级联清理）、稍后处理（保留草稿，下次启动再提示）。
- **历史详情页**：内嵌 AVAudioPlayer 薄封装播放器（播放/暂停、进度、倍速、总时长）；提供"删除音频"（二次确认）与"在 Finder 中显示"；无音频或音频已删除时优雅降级。
- 快照写失败仅呈现"自动保存失败"警告，不阻断录制，与 MeetingsStore"失败必须可观察"约束一致。
- 音频写入发生在会话消费循环而非实时音频线程，不改变 AudioCaptureService 的 tap 与转换管线。

### 时间轴与边界

- 全程遵循 ADR-0001：暂停不写入音频，音频偏移、片段时间戳、duration 均为排除暂停的录制时间轴，续录不产生空洞。
- 空会议边界：有音频即有草稿，不以有正式片段为准；无正式片段的中断会议可继续或放弃，"结束并生成"遵循现有空会议规则。

## Testing Decisions

- 好测试只断言外部行为：磁盘上的文件内容、存在性与可解码性，会话的转写结果与完成状态；不断言内部调用次数或私有状态。
- **零新增 mock 协议**：主接缝复用 MeetingSession 现有依赖注入（ScriptedCapture、TranscriberStub、ChatStub、真实 MeetingsStore + 临时目录）；音频与草稿写入使用真实实现，磁盘文件即断言对象。
- 文件存取层测试：真实临时目录覆盖 WAV 持续写入与头部回填、截断 WAV 的头部修复、草稿读写与删除、中断扫描、级联删除、单独删除音频；故障注入沿用仓库现有手法（目录替换为普通文件、POSIX 权限）。
- MeetingSession 测试：推样本后磁盘 WAV 时长正确；落定即写与兜底快照（间隔注入极短值，墙钟沿用 TestClock 模式，不真实等待）；恢复续录不重复提交已落定音频、尾部重新识别；完成与放弃清理草稿；空会议边界；自动保存失败可观察且录制继续。
- 恢复协调测试：残留草稿被扫描为中断会议；三种处置与稍后处理各自的文件清理/保留结果；正常完成与放弃后无残留草稿。
- Prior art：MeetingSessionTests 的替身与并发断言模式、MeetingsStoreTests 的临时目录与故障注入、WAVEncoderTests 的字节级断言。
- 播放器与恢复面板为 SwiftUI 薄层，手动验证，不写 UI 自动化测试。

## Out of Scope

- 点击正式片段跳转音频对应位置的文本联动（数据层面无阻碍，后续单独立项）。
- AAC 等音频压缩。
- 云同步与分享导出 UI（Finder 显示除外）。
- 以保存的音频重新转写/重新生成纪要的产品功能（格式上不阻断未来实现）。
- 为既有历史会议补音频（历史音频未留存，无法补）。
- 播放器与恢复面板的 UI 自动化测试。
